# Ручной workflow / crew-dispatcher v0.1

Это договорённость о данных и переходах для будущего движка, а не реализованный диспетчер. Сейчас все изменения карточки и передачи поручений выполняются вручную.

## Источник истины

Одна задача — один файл `tasks/<id>.md`. YAML-заголовок хранит текущие значения; разделы ниже — контекст, решение о маршруте, результат и историю. [TASKS.md](TASKS.md) только ссылается на карточки. Не создавай вторую доску статусов в других документах.

### Поля карточки

| Поле | Правило |
| --- | --- |
| `schema_version` | `1`: версия текущей формы карточки |
| `id` | Уникальное имя файла без `.md`; после создания не меняется |
| `project` | Один project key из [PROJECTS.md](PROJECTS.md) |
| `type` | Одно из `code`, `research`, `docs`, `review`, `automation`, `portfolio`; наличие типа не разрешает автоматизацию |
| `priority` | `now`, `soon` или `later`; не запускает работу |
| `role` | Одна основная Role из [ROLES.md](ROLES.md) |
| `executor` | Один Executor из [EXECUTORS.md](EXECUTORS.md) или `null` до маршрутизации |
| `model` | Точное имя выбранной модели или `null`; для Ollama обязательно при маршрутизации |
| `status` | Одно из девяти значений ниже |
| `attempt` | Целое число начатых запусков, изначально `0`; увеличивается только при входе в `running` |
| `review` | `required` — boolean, `role` — `Reviewer`, `executor` и `model` назначаются отдельно. При `required: false` оба значения `null` |
| `output` | Одна логическая ссылка `project_key:relative/path` на основной результат |
| `created`, `updated` | Даты `YYYY-MM-DD`; `updated` меняется при правке карточки |

Project key разрешается через `projects.<key>` в `config/local.yaml`. Часть после `:` — путь внутри этого корня: без абсолютного пути и выхода через `..` или симлинк. Эта форма используется также для источников в тексте; сама по себе она не является разрешением на доступ. Пустой корень требует уточнения через `needs_human`.

## Статусы и переходы

Основной путь: **`inbox → routed → running → verifying → needs_human → done`**.

| Status | Значение | Допустимые следующие статусы |
| --- | --- | --- |
| `inbox` | Карточка описана, маршрут ещё не подтверждён | `routed`, `needs_human`, `parked` |
| `routed` | Role/Executor, доступ, модель и ограничения проверены; работа ещё не запущена | `running`, `needs_human`, `parked` |
| `running` | Исполнитель начал конкретную попытку | `verifying`, `retry`, `failed`, `needs_human`, `parked` |
| `verifying` | Результат проверяется по критериям | `needs_human`, `retry`, `failed`, `parked` |
| `needs_human` | Нужна приёмка результата или ответ на явно записанный вопрос | `done`, `routed`, `verifying`, `failed`, `parked` |
| `done` | Критерии выполнены, проверки записаны, человек принял этот результат | Нет; новая работа получает новую карточку |
| `retry` | Зафиксирована неудачная попытка/проверка и решение попробовать снова | `routed`, `needs_human`, `failed`, `parked` |
| `failed` | Выполнение прекращено с причиной; успеха нет | `retry` по явному решению человека, либо `parked` |
| `parked` | Работа отложена с причиной и условием возврата | `inbox` по решению возобновить |

### Условия переходов

- Перед `routed` назначь основной Executor и, когда нужна проверка, `review.executor`. Проверь инструменты и локальные корни для нужных проектов. ChatGPT/Ollama без файловых инструментов получают разрешённые материалы вручную; это записывается в `Routing`.
- При `routed → running` увеличь `attempt` на один. В остальных переходах счётчик сохраняется; смена модели или Executor не сбрасывает историю.
- В `verifying` запиши результат проверок и их автора. При `review.required: false` отдельный Reviewer не нужен, но основной исполнитель всё равно проверяет критерии.
- `needs_human` не означает автоматический успех. Запиши конкретный вопрос, контекст и варианты в `Human Decision`; после ответа сохрани решение и причину следующего перехода.
- `needs_human → done` допустим только после успешной проверки и приёмки этого результата человеком. Разрешение начать задачу не является приёмкой ещё не существующего результата.
- Если ответ человека меняет объём/маршрут — вернись в `routed`; если нужна только повторная проверка уже имеющегося результата — в `verifying`. Если результата ещё нет, переход в `done` запрещён.
- Перед выходом из `running` исполнитель должен закончить или остановить текущую попытку; статус в Markdown сам не останавливает процесс.
- Для `retry` запиши причину, что изменится и основание повторного запуска. Возврат всегда через `routed`; автоматических повторов, фоновых таймеров и бесконечных циклов нет.
- Каждый переход запиши в `History`: дата, откуда/куда, номер попытки, кто изменил и почему. Старые результаты и ошибки не стирай.

## Шаблон карточки

Скопируй шаблон, замени ID, дату, project key и содержимое. Добавь только ссылку в `TASKS.md`.

````markdown
---
schema_version: 1
id: YYYY-MM-DD-short-name
project: skeletoncrew
type: docs
priority: soon
role: Writer
executor: null
model: null
status: inbox
attempt: 0
review:
  required: true
  role: Reviewer
  executor: null
  model: null
output: skeletoncrew:outputs/short-name.md
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
---
# Название

## Goal
Один ожидаемый результат.

## Context
Логические ссылки, факты с датами, неизвестное.

## Constraints
Разрешённые изменения, инструменты, расходы и внешние действия.

## Expected Output
Формат и содержание результата из поля output.

## Done Criteria
- [ ] Проверяемый критерий.

## Routing
Маршрут не подтверждён. Перед routed записать инструменты, доступ и готовое поручение; значения Role/Executor берутся из заголовка.

## Result
Результата пока нет. После выполнения: логическая ссылка и сведения о попытке.

## Verification
Проверка не выполнена. После проверки: автор/сеанс, способ, вывод и ограничения.

## Human Decision
Решения пока нет. При needs_human: вопрос; после ответа — решение человека о конкретном результате или дальнейшей работе.

## History
- YYYY-MM-DD: создана карточка, status=inbox, attempt=0; автор и основание.
````

До реализации crew-dispatcher v0.1 это проверяемая вручную форма. Парсера, валидатора переходов и запускателей в репозитории нет.

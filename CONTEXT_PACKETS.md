# Контекст для Executor

Пакет контекста объясняет выбранному Executor работу в назначенной Role. Обычно это разделы карточки; отдельный файл в `contexts/` нужен для объёмного или повторно используемого материала. Он ссылается на ID карточки и не хранит копию текущего статуса или маршрута.

## Минимальное содержимое

1. ID карточки, цель и критерии результата.
2. Project key, его инструкции и логические ссылки на нужные источники.
3. Факты с датой проверки, неизвестное и ограничения свидетельств.
4. Границы чтения, записи, запуска, публикации и затрат.
5. Ожидаемый формат и логическая ссылка на результат.

Поля `role`, `executor`, `model` и `review` читаются из карточки при передаче, а не задаются повторно в отдельном prompt. При смене маршрута обновляется карточка.

## Публичное и локальное

В публичном тексте используй `project_key:relative/path`, например `rrm:AGENTS.md`. Перед запуском человек разрешает project key через `config/local.yaml`. Подставленные абсолютные пути допустимы в локальном сеансе, но не возвращаются в публичный prompt, отчёт или карточку.

Если Executor не имеет доступа к файлам, передай только разрешённые фрагменты с логическими именами источников. Не отправляй весь `config/local.yaml`, секреты и постороннюю переписку. Путь сам по себе не предоставляет доступ.

## Достоверность

- **Проверено сейчас:** способ и дата текущего наблюдения.
- **Записано в источнике:** историческое свидетельство, не новая проверка.
- **Предложение:** действие ещё не выполнено.
- **Неизвестно:** данных недостаточно; нельзя дополнять догадкой.

Конкретный контекст и факты первой задачи находятся только в [её карточке](tasks/2026-09-21-rrm-pr-case.md), чтобы описание проекта и его состояния не расходилось между документами.

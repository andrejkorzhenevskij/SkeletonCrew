# Role: функциональная ответственность

Роль описывает **какую работу выполняют**. Механизм выполнения выбирается отдельно в [EXECUTORS.md](EXECUTORS.md). Например: `role: Writer`, `executor: Codex`; или `role: Classifier`, `executor: Ollama`.

| Role | Задача | Проверяемый результат |
| --- | --- | --- |
| `Dispatcher` | Уточнить поручение, определить границы и выбрать маршрут | Одна карточка с критериями готовности и отдельными Role/Executor |
| `Developer` | Код, диагностика, исправления, Git | Изменение и подходящая проверка в разрешённых границах |
| `Writer` | README, объяснение, портфолио-кейс, резюме текста | Текст, подтверждаемый источниками, с явно отмеченными неизвестными |
| `Classifier` | Распределить входные данные по заданным категориям | Метка для каждого элемента, причина и неопределённость; без выполнения действий по меткам |
| `Researcher` | Найти и сопоставить источники | Выводы, ссылки, даты и ограничения |
| `Reviewer` | Проверить результат по критериям карточки | Замечания, выполненные проверки и вывод для человека |

Названия в первом столбце — допустимые значения `role`. Основная работа имеет одну роль; отдельный этап проверки использует `review.role: Reviewer`. Сложное поручение разбивается на отдельные карточки, когда результаты требуют разных основных ролей.

Один Executor может выполнять разные роли последовательно. Если проверку делает тот же сеанс, запиши «самопроверка». Даже одинаковые названия Executor в разных сеансах сами по себе не доказывают независимость ревью: его происхождение указывается в `Verification`.

Капитан — человек, задающий поручение и принимающий результат через `needs_human`. Это участник процесса вне списка программных исполнителей.
